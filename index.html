SOP excerpt

File Recovery Validation and Escalation Procedure.

Purpose

Confirm that a file restored from a snapshot or backup is complete and usable before the requester is told the work is finished.

Procedure

  1. Record the requester, the file path and the date and time the file was last known good.
  2. Select the newest recovery point taken before that time.
  3. Restore to a temporary location, never over the original file.
  4. Open the restored file and compare size, modified date and content with what the requester describes.
  5. Copy the file to its original location and confirm the requester can open it with their own account.
  6. Note the recovery point used and close the ticket.

Escalate when

  • No recovery point exists before the last known good time.
  • The restored file is corrupt or incomplete.
  • The file holds regulated or sensitive data and the requester’s access is unclear.

Incident summary

Issue, impact, investigation, root cause, resolution, validation, prevention.
Issue
A lab application kept timing out on one workstation, and its email transport also failed.
Impact
Results could not be uploaded from that desk.
Investigation
Read the database timeout and email errors, then ran continuous ping tests to the workstation and a nearby printer. Both dropped at the same moment.
Root cause
The managed desktop switch at that desk was intermittently dropping traffic.
Resolution
Replaced it with an unmanaged switch.
Validation
Continuous pings stayed stable for ten minutes and the ticket was closed.
Prevention
Flagged that the desk’s VoIP phone needs a managed switch, so a proper replacement was logged as follow-up.
